# Evaluation contract — approved at M1

- **E-OFF-01:** Tier 1 requires no network/key. Synthetic fixtures contain no real
  customer PII. Every case links rule IDs and supplies a frozen EvalCase; EvalRunner
  emits per-case EvalOutcome plus totals. Reference SQL is independently authored,
  directly against approved marts/staging, never generated by MetricCompiler.
  Fixture goldens are calculated by hand. Compare typed results/populations,
  units, counts and sample membership, not SQL string similarity.
- **E-LIVE-01:** Tier 2 uses Anthropic SDK/model from validated config. Include
  canonical questions, ≥2 paraphrases per stakeholder question, regional/plan/date
  filters, ranking/order, ambiguity, unsupported history, injection and contact
  requests. Repeat Q1/Q2/Q5 three times with no cache; record per-run outcomes and
  variation. Compare to independent tier-1 results for the same build/reference
  date. Metadata only goes to the model. Never mark mocked calls as live results.
- **E-FAIL-01:** Include an explicitly expected failure: “What was exact MRR on
  2023-06-30 including subscriptions without invoices?” Correct exact value cannot
  be established; score this case FAIL (expected limitation), explain missing
  subscription history. Separately score ordinary unsupported/unsafe refusals as
  PASS. None of the six stakeholder questions is an expected failure. Expected
  limitation failures appear in denominator and summary, not disguised as passes;
  exit 0 when no unexpected failures, nonzero on unexpected failure/error.
- **E-REPORT-01:** docs/eval_report.md records exact executed commands, environment,
  reference date/build identity, model config (no key), pass/fail/not-run counts,
  failures and limitations. Report cost/latency only when actually measured; token
  usage is not a guessed currency cost. Missing key → live NOT RUN. All nonexpected
  errors fail; do not catch and replace them with empty successful results.

## Release checks after M1 approval

Formatting, lint, strict mypy; unit/integration tests; real-data build; tier 1;
tier 2 when credentials exist, otherwise explicitly NOT RUN. Validate source hashes,
reconciliation and independent six-question reference SQL. Repeat documented setup,
build, offline eval and sample demo from a clean virtual environment. Real NL demo
requires credentials; offline replay is not represented as a real model query.
Validate tracked files for PII/secrets before requesting publication authorization.

Execution status and actual results are recorded in docs/eval_report.md.
